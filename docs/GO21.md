# Baki Go 21 — Product surface

Customer-facing 21-day AI nutrition coaching experience.

Coach app remains existing Baki Go. Go21 reuses portal tokens, enrollments, V2 brain, Timeline, Attention.

## Routes

| Who | Path |
|-----|------|
| Coach activate | Customers → detail → **開通 21 天 AI 陪跑** → `/customers/[id]/start-21d` |
| Coach attention | 陪跑中心 `/coaching` (Timeline / Attention — not the legacy customer form) |
| Customer entry | `/c/{portalToken}/go21` (opaque token; not guessable IDs) |
| APIs | `/api/coaching/portal/[token]/go21/{context,baseline,start,chat,goal}` |
| Reminder worker | `/api/coaching/go21/reminders/process` (cron secret) |

## Eligibility

Only experience-21d enrollments may access Go21 routes. Generic coaching portals receive 403.

## Lifecycle Day X

Authoritative Day 1 = `coaching_enrollments.started_at` (experience schedule).
`go21_started_at` gates chat onboarding only and does not shift Day X.
Checkpoint measurements count only on/after lifecycle anchor (ignore pre-cycle history).

## Structured data

Numeric fields require defensible evidence. Qualitative hydration (`今天水喝超少`) stores a note/signal — never invents `waterMl`.

## Photo + real-time vision

1. Customer attaches a photo in Go21 chat (optionally with text e.g. 「午餐」).
2. Client uploads to private `coaching-meal-photos` via existing meal photo API:
   - known primary slot → that slot
   - photo-only / unknown slot → `snacks` (storage only; **does not invent** breakfast/lunch/dinner)
3. Chat turn sets `photoUploaded: true` only after successful upload.
4. Server resolves the authoritative photo from the portal’s daily log (never trusts client storage paths).
5. Real-time vision (`observeCoachingMeals`) runs in the **same turn**; observation is cached on `coaching_meal_photos` (`067`).
6. Observation feeds AI Coach V2 as evidence (freeMessage + mealObservations) — not a calorie scanner.
7. Daily generation job reuses the cache when present to avoid duplicate vision spend.

Vision observation ≠ confirmed fact. Failed vision keeps the photo/meal and degrades chat gracefully.

## Conversation quality

Authoritative chat history is `coaching_ai_turns` (customer + coach). Vision evidence summaries are stored on customer-turn metadata and hydrated into V2 memory for next-turn recall without duplicate Vision calls. Client `clientRequestId` provides turn idempotency.

## Coaching Brain V3

Customer-facing coach instructions are principle-based (understand the current intention → recall real history when asked → maintain a coherent meal timeline → protect the live goal with judgment → respond naturally → intervene when useful). Backend extraction/persistence stays structured. Memory questions must be answered from recentTurns / today meals / vision — never replaced by generic fat-loss advice. Send UX: sending / failed+retry (same request id). Chat uses a fixed mobile shell so the newest bubble stays above the composer; the jump-latest control appears only when the user has left the bottom.

## Premium Coaching Brain — longitudinal understanding

Target feeling: 「它真的越來越懂我。」

Across the 21 days the coach builds a **durable, revisable personal understanding** of this customer (not just recent chat context):

- eating patterns, preferences, recurring difficulties
- situations that trigger problems
- approaches that work / do not work for this person
- links between behavior, timing, and their Goal

**Authority:** `coaching_enrollments.go21_understanding_json` (migration `069`). Deterministic consolidate-from-turn updates evidence and confidence; generation receives a compact `longitudinalUnderstanding` block. Understanding must survive across conversations and actually steer judgment — not exist only as a longer system prompt.

**Evidence rules:** Prefer remember / observe early. Do not invent patterns from insufficient evidence. Share a longitudinal insight only when confidence + evidence count clear the gate (and lifecycle stage allows). Contradicting days revise or weaken prior understanding. Different customers accumulate different profiles → different coaching behavior.

**Response freedom:** Current utterance mode comes first (report / advice / factual / help / plan / casual / memory check). Silence and brevity are valid. Do not force advice, praise, questions, nutrition education, Goal mentions, or vegetable/protein reminders every turn.

**Relationship arc:** Early learn & observe → middle recognize patterns & personalize experiments → later connect what was learned → Day 21 can explain what seemed to work for *this* person.

## Natural Conversation Layer

Understand the conversational move before coaching. Short replies in context often mean: correction（我是說…）、decision（吃沙拉）、confirmation（好）、rejection（不要）、continuation（那雞排呢）、temporal fix（我是說明天）、or misunderstanding repair.

When the customer corrects the AI: repair first, update understanding, do not defend or repeat the old interpretation, and only coach further if genuinely useful. Avoid health-app voice（朝著目標邁進／更均衡／搭配蛋白質／控制熱量／加油）unless that moment truly needs it. One short natural sentence is often enough.

Detection lives in `src/lib/go21/conversational-move.ts` and is injected as `conversationalMove` in the generation user prompt; the fixture path acknowledges these moves before goal-conflict / nutrition branches.

## Human Coach Voice

Go21 already has enough intelligence (goal, timeline, memory, vision, longitudinal understanding, conversational moves). The remaining failure mode was **customer-facing reply shape**: replies collapsing into a packed health-app format (risk → education → alternative → encouragement → follow-up) even when one natural sentence would do.

**Contract:** reason richly internally; speak with the minimum natural Taiwanese Traditional Chinese a mature LINE private coach would use. Opinion, disagreement, light joke, yes, no, “今天我不推”, one practical compromise, or acknowledge-and-stop are all valid. Do not force neutrality. Do not force every turn to include risk / nutrition education / alternative / Goal language / a question.

**Implementation:** `humanCoachReply` (replyShape / lengthHint / doNotForce / may) is injected beside `conversationalMove` in the live user prompt (`src/lib/go21/human-coach-voice.ts`). Goal stewardship no longer mandates “必須給替代／蛋白質清楚”. Free-message `decisionContext` is demoted to internal cues so the model does not narrate a nutrition report. Prompt version: `coaching_ai_v3_human_coach_voice_1`.

When something genuinely needs explanation, explain it. When safety requires seriousness, be serious. When the customer asks a detailed nutrition question, answer properly. When the moment only needs 「今天我不推雞排 😂」, that is enough.

## Temporal continuity

The coach must keep a coherent timeline across turns. Authoritative grounding is `buildGo21TemporalTimeline` (`todayEaten` / `openPlansForToday` / `doNotTreatAsCurrent`), fed by:

- turn `metadata.temporal` (utteranceKind, eventDate, mealSlot, relativeLabel) persisted on customer accept
- daily-log meal notes (eaten only — planned food is tagged `[計畫｜未食用]` in customer note, never written as a filled meal slot)
- relative day resolution for 剛剛／昨天／明天／後天 etc.

Generation (prompt + fixture) must not reinterpret historical mentions as tonight/today unless they remain in `openPlansForToday`. Ambiguous timing → no invented certainty. Goal-driven steering uses the same timeline so stale hamburger plans cannot become “今晚的漢堡”.

## Activation (coach → customer)

Activation must work for both existing and newly created CRM customers:

1. Customer detail **Baki Go 21** card loads via `/api/coaching/go21/status` (service role; timed out — never hangs on browser RLS).
2. **開通 21 天 AI 陪跑** flushes local→cloud, ensures the customer row, then opens `/customers/[id]/start-21d`.
3. `POST /api/coaching/experience-21d` upserts the cloud customer if missing, creates the experience-21d enrollment idempotently, and returns `portalToken` for `/c/{token}/go21`.

Do not depend on browser `customer_portal_tokens` RLS for the activation success path.

## Goal

- primary direction (orientation label)
- personal goal in the customer’s own words
- optional target weight (never fabricated)
- original + history for refinements

Set during first-time Go21 entry (after baseline). Existing enrollments without a goal keep working and are invited to set one. AI Coach V2 uses the goal as a professional steering anchor (no empty praise when choices conflict; still no mantra every turn). Day 7/14/21 guidance anchors reflections to real evidence only.
